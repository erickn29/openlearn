Выдай следующий урок по предмету: $ARGUMENTS

1. Определи секцию. Если ученик в треке — возьми первую по `order` секцию из `tracks/<track>/track.json`, где остались несданные уроки.
2. Прочитай `subjects/<slug>/progress.json` и `plan.md`.
3. Если предыдущий урок не сдан — не переходи дальше, а предложи доработку.
4. Вызови `teacher` для `lessons/lesson_N/`:
   - всегда: `theory.md`, `tasks.md`, `answer-key.md`;
   - если тема практическая (код, Dockerfile, docker compose, SQL, конфиг, скрипт) — ещё `checks.json`, `work/` и `work/README.md`.
     Практическую тему нельзя оформить как «опишите словами»: задание должно проверяться файлами.
   Перед этим передай учителю `market.md`, если он есть: урок по навыку из топа вакансий весит больше, чем урок «на всякий случай».
5. Проверь формат урока линтером — урок с нарушениями не показывай:

```sh
node .opencode/skills/lesson-generator/scripts/lint-lesson.mjs --lesson subjects/<slug>/lessons/lesson_N
```

Правила, которые ловит линтер: не больше 5 абзацев прозы, обязательные разделы «Зачем это в работе» и «Где это в работе», пример кода, оценка времени в шапке, 2–4 задания с ответами в ключе. Код `1` — верни урок учителю на доработку.

6. Проверь `checks.json`: список проверок не пустой, и каждой `type: run` задан `teardown`:

```sh
node .opencode/skills/lesson-checks/scripts/check.mjs --lesson subjects/<slug>/lessons/lesson_N --list
```

Если `teardown` нет — верни урок учителю на доработку, не показывай ученику.

7. Покажи теорию и задания, ключ ответов не раскрывай. Первой строкой назови объём: «Урок N из M · ~20 минут · практика 14».
8. Если урок файловый — объясни, куда класть работу: `subjects/<slug>/lessons/lesson_N/work/`, и как проверить локально (из `work/README.md`).
9. Напомни, как отправить работу: `/check` (текстовые ответы — сообщением, файлы — просто сохранить в `work/`).
